# Garmin comparison and scope

This matrix keeps the “best practical Karoo version” goal measurable. Garmin behaviour comes from Tymewear's current public [Garmin bike computer guide](https://www.tymewear.com/blogs/connectivity/garmin-bike-computers) and [threshold settings guide](https://www.tymewear.com/blogs/connectivity/setting-threshold-values). VitalBreathe status refers to this repository's source, automated tests, and the sanitised [physical validation record](VALIDATION.md). One Karoo 3 and VitalPro combination has been tested successfully; broader compatibility and endurance testing remain open.

| Capability | Public Garmin experience | VitalBreathe community beta | Evidence status |
| --- | --- | --- | --- |
| Direct breathing-sensor connection | Connect IQ app connects directly to the VitalPro breathing sensor | Direct BLE connection with shared-session ownership, bounded setup, reconnect backoff, valid-breath watchdog, and diagnostics | Connected and automatically recovered from two controlled outages on Karoo 3; broader firmware and contention coverage remains |
| Main VE signal | VE 30-second moving average is the recommended background-zone signal | Time-weighted live, 5s, 15s, 30s, and 60s VE; VE30 drives zones | Averaging and zone math tested |
| Personal ventilation zones | Endurance, VT1, VT2, Top Z4, and VO2max are entered from the rider's latest sport-specific threshold test | The same five ordered values are required, or all five can be left blank to disable zones safely; changes saved during a ride apply after that recording | Validation, boundaries, and ride-frozen settings tested |
| Visible breathing metrics | VE, BR, TV, HR, battery, charts, and optional external-load metrics | Separate VE, BR, TV, battery, graph, zone, and experimental MI fields plus a combined VE30/BR/TV/HR/battery dashboard | All nine fields are packaged; compact and full dashboards are physically readable on Karoo 3; MI remains unvalidated |
| Zone consistency | Garmin recommends VE30 for easier-to-follow colour changes | The dashboard, live/recorded zone totals, and FIT zone use VE30. The standalone VE field can show live, 5s, 15s, 30s, or 60s, and always uses that selected value for both its number and colour | Shared snapshot, freshness, elapsed-time, and threshold tests pass |
| Charts | Full-screen experience offers metric focus, four stacked views, and zoom | Full-page five-minute VE chart with labelled axes, 15s/30s/60s tap selection, optional zone bands, and honest reconnect gaps | Five-minute history, all three modes, and a reconnect gap were physically checked on Karoo 3; multi-metric charts and zoom are not implemented |
| Battery | Battery level is available as an optional display | Exact percentage from the standard BLE Battery Service, with retry and ten-minute refresh | Read, refreshed, and displayed on the tested VitalPro; not an independent charge measurement |
| FIT recording | Garmin records data and can synchronise it through linked Garmin/Tymewear accounts; optional Minute Volume Lap saving is exposed | Fresh BR/TV/raw VE and explicit VE30 records, optional personal fields, and the ride's five threshold values are written through Hammerhead's FIT extension API; five-zone session totals are added only when zones are configured and accumulate time | A live-at-start ride decoded strictly with valid CRCs, ordered metadata, and 65 complete records; third-party service import and configured-zone summaries remain open |
| Lap ventilation | Optional Minute Volume Lap data can be saved | No dedicated lap-average VE field; per-second VE is available for downstream calculation | Not implemented |
| BR/TV/HR/power/speed zones | Optional fixed zones can colour these metrics | VE zones only; HR is shown and used for optional MI, while power and speed are left to native Karoo fields | Deliberate reduced scope |
| Threshold test and account sync | Garmin account linking enables automatic Tymewear synchronisation; thresholds come from the Tymewear test | No Tymewear login, cloud sync, automatic threshold import, or threshold test | Not practical without an official Tymewear API |
| Failure visibility | Public guide offers setup and contention troubleshooting | Settings show Bluetooth phase, retry count, last-breath age, last error, and a permission retry | Physically exercised during reconnect testing on Karoo 3 |

## Deliberate limits

A dedicated lap-average VE field is deferred because the supported Hammerhead extension API exposes record and session FIT messages, not lap messages. Multi-metric stacked charts are also deferred until the current fields have been checked on real Karoo layouts. Account sync, automatic threshold import, and threshold testing should remain out of scope unless Tymewear provides an official API and permission to use it.
